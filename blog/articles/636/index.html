withSearch搜索器

https://www.kancloud.cn/manual/thinkphp6_0/1037590
搜索器的作用是用于封装字段（或者搜索标识）的查询条件表达式，一个搜索器对应一个特殊的方法（该方法必须是public类型），方法命名规范为：
searchFieldNameAttr
FieldName为数据表字段的驼峰转换，搜索器仅在调用withSearch方法的时候触发。

搜索器的场景包括：

  • 限制和规范表单的搜索条件；
  • 预定义查询条件简化查询；
例如，我们需要给User模型定义name字段和时间字段的搜索器，可以使用：
<?php
namespace app\model;

use think\Model;

class User extends Model 
{
    public function searchNameAttr($query, $value, $data)
    {
        $query->where('name','like', $value . '%');
    }
    
    public function searchCreateTimeAttr($query, $value, $data)
    {
        $query->whereBetweenTime('create_time', $value[0], $value[1]);
    }    
}

然后，我们可以使用下面的查询

User::withSearch(
     ['name','create_time'], 
     [
	'name'			=>	'think',
    	'create_time'	=>	['2018-8-1','2018-8-5'],
        'status'		=>	1
    ])
	->select();

最终生成的SQL语句类似于

SELECT * FROM `think_user` WHERE  `name` LIKE 'think%' AND `create_time` BETWEEN '2018-08-01 00:00:00' AND '2018-08-05 00:00:00'

同样的也能在模型中使用

<?php  
namespace app\common\model;
use think\facade\Db;			
// 构建出1,2,3,4这种字符串
use app\common\model\Category as CategoryModel;
class Goods extends \think\Model
{	

	public function searchGoodsCateIdAttr($query, $value)
	{
		$query->where('goods_cate_id','in', $value);
	}

	public function searchGoodsStatusAttr($query, $value)
	{
		$query->where('goods_status','=', $value);
	}

	public function searchGoodsNameAttr($query, $value)
	{
		$query->where('goods_name','like', '%'.$value.'%');
	}

	//搜索器的使用
	public function search1($cate_id,$goods_status,$goods_name,$page='10'){


        //根据url传过来的分类id，找出该分类下面的所有子分类id
		$cateChilerenId='';
        if(!empty($cate_id)){

        	$cates=Db::name('Category')->field('id,parent_id,cate_name')->select();

			// 构建出1,2,3,4这种字符串
			$_cateChilerenId=(new CategoryModel())->getChildrenIdStr($cates,$cate_id);

			$cateChilerenId=$cate_id.','.$_cateChilerenId;//先把当前的id放到字符串中

		}
		

		if(empty($cate_id)){
			$goodsData=Goods::name('goods')
			->alias('a')
			->join('category b','a.goods_cate_id=b.id')
			->field('a.*,b.cate_name')
			->order('listorder asc')
			->order('goods_id desc')
			->withSearch(
				['goods_status','goods_name'],
				[
				'goods_status'=>$goods_status,
				'goods_name'=>$goods_name
				])
			->paginate(['list_rows'=> $page,'query'=>request()->param()]);
		}

		if(!empty($cate_id)){
			$goodsData=Goods::name('goods')
			->alias('a')
			->join('category b','a.goods_cate_id=b.id')
			->field('a.*,b.cate_name')
			->order('listorder asc')
			->order('goods_id desc')
			->withSearch(
				['goods_cate_id','goods_status','goods_name'],
				[
					'goods_cate_id'=>$cateChilerenId,
					'goods_status'=>$goods_status,
					'goods_name'=>$goods_name
				])
			->paginate(['list_rows'=> $page,'query'=>request()->param()]);
		}
		//echo Goods::getLastSql();
        return $goodsData;		
	}

}
?>

控制器中

use app\common\model\Goods as GoodsModel;
//商品列表
$goods_model=new GoodsModel();
$goodsData=$goods_model->search1($cate_id,$goods_status,$search_key);

withSearch(['goods_status','goods_name'], [...])会遍历第一个数组里的每个字段名，按search+ 驼峰 +Attr规则拼出方法名，然后自动调用：

  • goods_status→searchGoodsStatusAttr($query, $goods_status)

  • goods_name→searchGoodsNameAttr($query, $goods_name)

前提是模型里确实存在这些方法，否则框架静默跳过，不报错。

withSearch本质上是在构建查询语句

withSearch本身不执行 SQL，它只是把搜索器里的条件挂到查询构造器$query上。真正的 SQL 要等你调用paginate()、select()、find()这些终结方法时才生成并执行。
withSearch的第二个参数（$params数组）的键名必须和第一个数组里的字段名一致。
withSearch(
    ['goods_status', 'goods_name'],   // 字段名
    [
        'goods_status' => $goods_status,  // 键名对应
        'goods_name'   => $goods_name,    // 键名对应
    ]
)

withSearch=声明要按哪些字段搜索 + 传入搜索值，框架据此自动调用对应的搜索器方法，把where条件挂到查询构造器上，最后paginate/select时才生成并执行 SQL。

Goods::name('goods')

例如，在这个Goods模型中，可以使用 Goods::name('goods') 来访问数据表，作用等同于Db::name('表名')。

Goods是你的模型类。模型类本身也支持链式查询方法（底层会转发给查询构造器）

当前场景里，既然已经写了Goods模型，其实更“模型化”的写法是直接用模型本身：

Goods::alias('a')->join(...)->field(...)->withSearch(...)->paginate(...);

不需要再额外name('goods')，因为模型会自动关联到对应的数据表（通常就是goods）。

TP6 模型会“自动推导”表名

TP6 的模型有一个默认行为：它会根据模型类的名称自动去对应数据表。

规则是：把类名转为小写+下划线，再拼上数据库配置里的前缀。

  • 如果你的模型类叫Goods，它会自动去找goods表（假设无前缀）。

  • 如果你的模型类叫UserType，它会自动去找user_type表。

所以在未指定 protected$name ='goods'; 明确表名的情况下，框架会按类名自动推导表名；如果类名和实际表名对不上，才需要手动用Db::name 或者 Goods:: 或者 Goods::name('goods') 或者$this->

注意：Goods::name()走模型静态代理，仍然能触发模型特性（比如withSearch）。Db::name()返回查询构造器，不触发模型特性（获取器、搜索器、关联等）
在模型方法里能不能用$this，取决于你是在“实例方法”还是“静态调用”场景下。$this是 PHP 里的一个特殊变量，它指向当前对象实例。

在模型内部写普通方法（实例方法）时，本来就可以用$this

class Goods extends Model
{
    protected $name = 'goods'; // 指定表名与$this之间无关！不指定也能用$this

    public function getList()
    {
        // $this 就是当前模型实例，可以直接链式查询
        return $this->alias('a')
            ->join('category b', 'a.goods_cate_id=b.id')
            ->field('a.*,b.cate_name')
            ->select();
    }
}

控制器里：

$goods = new GoodsModel();
$goods->getList();   // 走实例方法，$this 有效

指定表名

在 TP6 模型里，通常会在类顶部用protected属性指定表名，这是模型的标准做法。

namespace app\common\model;

class Goods extends \think\Model
{
    protected $name = 'goods';   // 指定数据表名（不带前缀）
    // 或者
    protected $table = 'tp_goods'; // 指定完整表名（带前缀）
}

name和$table的区别

属性含义是否自动加前缀
protected $name = 'goods';表名（不含前缀）✅ 自动加前缀
protected $table = 'tp_goods';完整表名❌ 不自动加前缀

一般推荐用$name，因为前缀在数据库配置里统一管理，换前缀时不用改模型。

protected $name的作用是覆盖默认的自动推导规则。只有在“模型类名”和“实际表名”对不上时，才必须用它。

当然我个人还是建议每个模型，都明确表名。
