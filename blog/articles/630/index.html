url()助手函数

https://www.kancloud.cn/manual/thinkphp6_0/1037508

系统提供了一个url助手函数用于完成相同的功能，例如：

url('index/blog/read', ['id'=>5])
    ->suffix('html')
    ->domain(true)
    ->root('/index.php');

这个方法可以用于模板中，比如

<a href="{:url('flink/del',array('id'=>$vo.id))}">删除</a>

最终渲染出来的地址就是：href="/tp6-eshop/code/qingadmin/flink/del.html?id=2"

末尾带的del.html与url_html_suffix设置有关，设置在config/route.php中

模板语法 {:函数()}含义

{:xxx}：**执行 PHP 表达式并输出结果，
不管里面是 PHP 原生函数`date()`，还是 TP 自定义助手函数`url()`，都要用 `{:}` 开头，不然原样输出。
- {date('Y-m-d', $vo.time)} → 没有，原样打印文本
- {:date('Y-m-d', $vo.time)} → 执行表达式
- {:url('fapiao/add')} → : 执行 TP 的 url 助手函数

{:函数名(参数)}：直接调用函数（适合 url、date 等），必须加冒号{:}

public function upload(){
    // 获取表单上传文件 例如上传了001.jpg
    $file = request()->file('image');
    // 上传到本地服务器 topic 是指上传到的目录名
    $savename = \think\facade\Filesystem::putFile( 'topic', $file);
    // 如果你希望上传的文件是可以直接访问或者下载的话，可以使用public存储方式。

}

非public的上传路径：\runtime\storage\topic\20261104\xxx.jpg，但是这个上传目录runtime是一个临时目录，正常情况我们需要修改上传的路径，在项目目录\config\filesystem.php中修改，默认配置如下：

return [
    // 默认磁盘
    'default' => env('filesystem.driver', 'local'),
    // 磁盘列表
    'disks'   => [
        'local'  => [
            'type' => 'local',
            'root' => app()->getRuntimePath() . 'storage',
        ],
        'public' => [
            // 磁盘类型
            'type'       => 'local',
            // 磁盘路径
            'root'       => app()->getRootPath() . 'public/storage',
            // 磁盘路径对应的外部URL路径
            'url'        => '/storage',
            // 可见性
            'visibility' => 'public',
        ],
        // 更多的磁盘配置信息
    ],
];

'default'=> env('filesystem.driver','local') 中的local 指代的是 使用的disks['local']的配置。比如我可以改成这样：

public function upload(){

        validate(['image'=>'fileSize:10240|fileExt:jpg|image:200,200,jpg'])

返回JSON，json（）助手函数

通常上传都是异步的，这时候操作完上传，需要返回一个json，这时候可以直接使用json函数，就会自动设置header(Content-Type: application/json; charset=utf-8)

在控制器中：

public function index()
{
    $data = ['name' => 'thinkphp', 'status' => '1'];
    return json($data);
}

注意：ThinkPHP 6 默认已开启中文不转义（JSON_UNESCAPED_UNICODE）

如果你确实需要在模板文件里输出 JSON

有时你需要在 HTML 模板的<script>标签里，把后端数据转成 JS 对象，这时才会涉及模板输出。核心问题是模板默认会对变量进行 HTML 转义，直接输出 JSON 字符串会导致引号变成&quot;，前端 JS 解析报错。

方法一：使用{:json_encode()}配合|raw过滤器

<script>
    // 模板中直接对数组变量进行 json_encode 并阻止转义
    var data = {:json_encode($data)|raw};
    console.log(data);
</script>

这里|raw的作用是告诉模板引擎不要对json_encode的结果进行htmlentities转义。

方法二：在控制器中预先处理，模板用|raw输出

// 控制器
View::assign('json_data', json_encode($data));
<!-- 模板 -->
<script>
    var data = {$json_data|raw};
</script>

这种方式效果与上面一致，但把json_encode的逻辑移到了控制器。

避坑提醒

  • 不要写return $data;（直接返回数组）：TP6 会尝试走模板渲染流程，导致输出 HTML 或报错，而不是 JSON。

  • 不要用echo json_encode($data);：这会绕过框架的响应生命周期，导致日志、中间件等功能失效。

  • 模板中若不加|raw：JSON 字符串里的引号会被转义，前端JSON.parse或直接赋值给 JS 变量时会出错。

关于field

https://www.kancloud.cn/manual/thinkphp6_0/1037542

在查询操作中field方法是使用最频繁的。

Db::table('user')->field('id,title,content')->select();

里使用field方法指定了查询的结果集中包含id,title,content三个字段的值。执行的SQL相当于：

SELECTid,title,contentFROMuser

可以给某个字段设置别名，例如：

Db::table('user')->field('id,nickname as name')->select();
执行的SQL语句相当于：

SELECT id,nicknameasnameFROMuser

获取所有字段

Db::table('user')->select();
Db::table('user')->field('*')->select();
上面的用法是等效的，都相当于执行SQL：
SELECT *FROMuser

用于写入

除了查询操作之外，field方法还有一个非常重要的安全功能--字段合法性检测。field方法结合数据库的写入方法使用就可以完成表单提交的字段合法性检测，如果我们在表单提交的处理方法中使用了：

Db::table('user')->field('title,email,content')->insert($data);

即表示表单中的合法字段只有title,email和content字段，无论用户通过什么手段更改或者添加了浏览器的提交字段，都会直接屏蔽。因为，其他所有字段我们都不希望由用户提交来决定，你可以通过自动完成功能定义额外需要自动写入的字段。

                           ->paginate(5);
SELECT a.*, b.goods_thumb, c.username, c.mobile
FROM tp_comment AS a
INNER JOIN tp_goods AS b ON a.goods_id = b.goods_id
INNER JOIN tp_user AS c ON a.user_id = c.id
ORDER BY a.id DESC
LIMIT 0, 5;

注意join vs leftJoin的区别

join() = INNER JOIN（内连接）只返回两张表中都匹配上的行

comment (a)          user (c)
  id=1, user_id=100     id=100, mobile=...
  id=2, user_id=999     id=100...

评论1的 user_id=100 → user 表有 → 保留

评论2的 user_id=999 → user 表没有（用户被删了）→ 丢弃

用 SQL 表达：FROM comment a INNER JOIN user c ON a.user_id = c.id

leftJoin() = LEFT JOIN（左连接）

以左表（comment）为准，左表每一行都保留；右表匹配不上就填 NULL。

评论1 → 匹配到 user → 保留，带 username/mobile

评论2（user_id=999 不存在）→ 也保留，但 c.username、c.mobile 都是 NULL

用 SQL 表达：FROM comment a LEFT JOIN user c ON a.user_id = c.id

对比表

join(INNER)leftJoin(LEFT)
左表不匹配的行丢弃 保留（右表字段为 NULL）
右表不匹配的行丢弃 丢弃（左连接不看右表多余行）
结果行数两表交集≥ 左表行数
典型场景一定要关联数据、关联不上就不要主表数据必须展示，关联信息可有可无

删

当id设置为表的主键的时候，可以用下面的方法删除：

$res = Db::name($dbname)->delete($id);

上面这个删除有可能会报错。 Db::name($dbname)->delete($id) 这种写法依赖 ThinkPHP 自动将传入的值解析为主键条件。如果目标表 $dbname 对应的数据表没有设置主键，或者主键名不是默认的 id，框架就无法执行。会抛出错误：报错了 没有条件不会执行删除操作。

建议改为：

$res = Db::table($dbname)->where('id', $id)->delete();

在父类中进行模板赋值

模板赋值：https://www.kancloud.cn/manual/thinkphp6_0/1037609

比如现在有个父类控制器

// controller/Base.php
class Base extends BaseController {...}

// controller/Other.php
class Other extends Base {
    return view('', [
       'data' => ....
    ]);
}

现在比如有个变量，用户登录的用户名，需要在多个控制器中的模板中渲染一样的数据

<li>用户名：{$loginUser}</li>

这时候给每个控制器模板渲染中单独添加一个 $loginUser 变量肯定很啰嗦，这时候就可以在父类中添加一个统一的模板赋值

use think\facade\View;
class Base extends BaseController
{
    public function initialize()
    {
        // echo '我是base';
        $loginAdmin = session('adminSessionData');
        // 模板赋值 https://www.kancloud.cn/manual/thinkphp6_0/1037609
        // 在公共父类上面 通过模板赋值的方式 将用户名传递过去
        View::assign('loginUser',  $loginAdmin['user_name']);
    }
...
}

这样只要是继承了Base父类的子类，所渲染的模板中都会自动添加这个loginUser的变量，可以直接用。

在 ThinkPHP 的控制器里，initialize()方法会在控制器实例化之后、调用具体操作方法之前自动执行，你不需要手动调用它。

 public function render($request, Throwable $e): Response

分页

https://www.kancloud.cn/manual/thinkphp6_0/1037638

ThinkPHP内置了分页实现，要给数据添加分页输出功能变得非常简单，可以直接在Db类查询的时候调用paginate方法：

// 查询状态为1的用户数据 并且每页显示10条数据
$list = Db::name('user')->where('status',1)->order('id', 'desc')->paginate(10);

// 渲染模板输出
return view('index', ['list' => $list]);

模板文件中分页输出代码如下：

<div>
<ul>
{volist name='list' id='user'}
    <li> {$user.nickname}</li>
{/volist}
</ul>
</div>
{$list|raw}

默认情况下，生成的分页输出是完整分页功能，带总分页数据和上下页码，分页样式只需要通过样式修改即可。如果你需要单独获取总的数据，可以使用

// 查询状态为1的用户数据 并且每页显示10条数据
$list = Db::name('user')->where('status',1)->order('id' ,'desc')->paginate(10);
// 获取总记录数
$count = $list->total();
return view('index', ['list' => $list, 'count' => $count]);

支持传入总记录数而不会自动进行总数计算，例如：

// 查询状态为1的用户数据 并且每页显示10条数据 总记录数为1000
$list = Db::name('user')->where('status',1)->paginate(10,1000);
// 获取分页显示
$page = $list->render();

return view('index', ['list' => $list, 'page' => $page]);

模板中渲染一样：

<div>
<ul>
{volist name='list' id='user'}
    <li> {$user.nickname}</li>
{/volist}
</ul>
</div>
{$page|raw}

对于UNION查询以及一些特殊的复杂查询，推荐使用这种方式首先单独查询总记录数，然后再传入分页方法

如果你仅仅需要输出一个 仅仅只有上下页的分页输出，可以使用下面的简洁分页代码：

// 查询状态为1的用户数据 并且每页显示10条数据
$list = Db::name('user')->where('status',1)->order('id', 'desc')->paginate(10, true);

// 渲染模板输出
return view('index', ['list' => $list]);

由于简洁分页模式不需要查询总数据数，因此可以提高查询性能。
